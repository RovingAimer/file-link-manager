# Windows 文件链接管理器设计文档

- 状态：公开架构说明
- 日期：2026-08-07
- 目标平台：Windows 10/11 x64
- 技术基线：C#、WPF、.NET 10 LTS、MVVM

## 1. 产品目标

构建一个便携式 Windows 桌面应用，用 Windows 原生文件链接能力为现有文件或目录创建等价访问路径，并记录由本软件完成的操作。

用户指定已存在的源路径 `A:\xxx1` 和尚不存在的链接路径 `B:\xxx2`。创建成功后，访问 B 等价于访问 A；A 保持原位，不发生复制、移动或重命名。

首版包含：

- 创建文件符号链接、目录符号链接、文件硬链接和目录联接（Junction）。
- 手动输入、粘贴及资源管理器选择路径。
- 显示每种链接的作用、限制、实时校验和创建结果。
- 按设备记录、查询、检查和安全删除由本软件创建的链接。
- 显示当前有效链接数与历史创建总数，并保留删除历史。

首版不扫描或导入由其他工具创建的链接，不移动源内容，不支持目录硬链接，不提供批量创建、云同步或远程设备管理。

## 2. 用户体验

### 2.1 应用结构

主窗口采用左侧导航双页面布局：

1. **创建链接**：完成类型选择、路径输入、校验、预览和创建。
2. **链接记录**：完成设备切换、统计、筛选、状态检查和删除。
3. **关于**：显示版本、当前设备身份摘要、数据位置和备份入口。

视觉采用简洁的 Windows 11 风格、Segoe UI 字体和系统强调色，不引入第三方 UI 框架。应用每次启动均通过 `requireAdministrator` 清单请求管理员权限。

### 2.2 创建链接

创建页顶部提供四张可快速选择的类型卡片。每张卡片始终显示一句效果说明及主要限制，不能只依赖悬浮提示：

| 类型 | 用户提示 | 约束 |
| --- | --- | --- |
| 文件符号链接 | 为文件增加可跨卷的等价路径 | 源必须是文件 |
| 目录符号链接 | 为目录增加可跨卷的等价路径 | 源必须是目录 |
| 文件硬链接 | 两个路径共享同一个文件内容 | 仅文件；必须同卷 |
| 目录联接 | 将一个目录路径重定向到本机另一目录 | 仅目录；可跨本机卷；不支持映射网络卷 |

源路径输入支持直接编辑、粘贴，以及根据链接类型打开文件或文件夹选择器。源必须已经存在。由于应用始终提升权限运行，首版不承诺从普通权限资源管理器拖放文件，以免受到 Windows 完整性级别隔离影响。

链接路径支持直接编辑。点击“选择位置”时先选择父目录，再输入或接受建议的链接名称；界面最终始终显示完整路径。链接路径本身必须不存在，但父目录必须存在。

界面实时显示：

```text
B:\xxx2（新链接） → A:\xxx1（现有源）
```

只有全部校验通过时才启用“创建链接”。创建成功后清晰展示结果并刷新当前设备的记录与统计。

### 2.3 链接记录

记录页顶部包含设备选择器、当前有效数和历史创建总数。列表支持：

- 按有效、失效、已删除状态筛选。
- 按源路径或链接路径搜索。
- 查看类型、创建时间、最近检查时间与状态原因。
- 打开链接所在目录、立即重新检查、删除链接。

删除前显示二次确认，明确列出将删除的链接入口和不会受影响的源路径。删除完成后记录保留并写入删除时间。

应用进入记录页时，在后台检查当前设备尚未删除的记录；用户也可手动重新检查。其他设备的路径不得在当前设备上检查，其状态显示为该设备最后一次运行时保存的结果，并标注“离线设备快照”。

## 3. 技术架构

### 3.1 分层

应用采用单进程、单实例 MVVM 架构，分为四个边界清晰的部分：

- **Presentation**：WPF 视图、ViewModel、导航、对话框和 UI 状态；不直接调用 Win32 API 或读写 JSON。
- **Application**：创建、检查、删除、筛选和统计用例；编排验证、原生操作与记录存储。
- **Domain**：链接类型、请求、记录、设备身份、状态及验证错误等纯模型。
- **Infrastructure**：Win32 文件链接引擎、设备身份读取、JSON 存储、文件选择器和单实例锁。

核心接口保持窄而明确：

```csharp
public interface IFileLinkService
{
    LinkValidationResult Validate(LinkRequest request);
    Task<LinkInspection> CreateAsync(LinkRequest request, CancellationToken cancellationToken);
    Task<LinkInspection> InspectAsync(string linkPath, CancellationToken cancellationToken);
    Task DeleteAsync(LinkRecord record, CancellationToken cancellationToken);
}

public interface ILinkRecordStore
{
    Task<LinkDatabase> LoadAsync(CancellationToken cancellationToken);
    Task SaveAsync(LinkDatabase database, CancellationToken cancellationToken);
}
```

`LinkRequest` 明确区分 `SourcePath` 与 `LinkPath`，避免使用含义易反转的 `TargetPath`。UI、日志和错误消息统一采用“链接路径 → 源路径”的方向。

### 3.2 原生链接引擎

- 符号链接通过 `CreateSymbolicLinkW` 创建。
- 文件硬链接通过 `CreateHardLinkW` 创建。
- 目录联接先创建空的链接目录，再通过 `CreateFileW`、`DeviceIoControl` 和 `FSCTL_SET_REPARSE_POINT` 写入挂载点重解析数据；写入失败时只清理该次创建的空目录。
- 检查操作读取文件属性、重解析点标记、最终路径和文件标识，返回统一的 `LinkInspection`。
- 删除文件链接使用 `DeleteFileW`，删除目录链接入口使用 `RemoveDirectoryW`，不得递归删除。
- 所有 Win32 错误在基础设施边界转换为包含操作、路径和可读原因的领域异常；ViewModel 不解析原始错误码。

路径在验证前转换为绝对规范路径，但保留用户用于显示的原始输入。比较路径时不区分大小写，并正确处理盘符根路径、UNC 路径、尾部分隔符和长路径前缀。任何超出所选链接类型能力的路径都在调用原生 API 前被拒绝。

### 3.3 创建流程

1. 规范化路径并运行类型、存在性、父目录、同卷及网络路径校验。
2. 调用原生引擎创建链接。
3. 立即检查新链接，确认类型及指向符合请求。
4. 创建记录并原子写入数据文件。
5. 刷新 UI 状态和统计。

若原生创建失败，不写记录。若链接已创建但记录保存失败，应用不得谎报整体失败；应显示“链接已创建但未登记”，保留请求信息并提供重试登记操作。

### 3.4 安全删除流程

1. 根据记录重新检查当前链接路径。
2. 符号链接或联接必须匹配记录中的重解析点类型和源路径。
3. 硬链接必须与创建时记录的卷序列号和文件标识一致；即使原始源路径后来被外部移除，也不依赖路径猜测身份。
4. 若路径已不存在，将记录标记为失效，由用户确认后可标记为已删除。
5. 若路径被普通文件、普通目录或不同链接替换，标记为冲突并拒绝删除。
6. 验证通过后只删除链接入口，再确认源路径仍存在并更新记录。

## 4. 便携数据与多设备

数据文件固定为应用目录下的 `data/link-records.json`。应用以自包含便携方式发布，不把业务数据写入用户配置目录。

设备身份由注册表 `HKLM\SOFTWARE\Microsoft\Cryptography` 下的 `MachineGuid` 计算 SHA-256 摘要，摘要作为稳定键；同时保存 `Environment.MachineName` 作为显示名称。设备改名时键不变并更新显示名称；设备名称相同但 MachineGuid 不同时视为不同设备。原始 MachineGuid 不写入数据文件。

数据根对象包含模式版本、设备集合和链接记录。每条记录至少保存：

- 记录 ID、设备键和创建时的设备显示名称。
- 链接类型、规范化源路径、规范化链接路径。
- 创建后检查所得的验证指纹：重解析点类型及规范化目标，或硬链接的卷序列号及文件标识。
- 创建时间、最近检查时间、删除时间。
- 状态：`Valid`、`Missing`、`Conflict`、`Deleted` 或 `Unknown`。
- 最近检查的错误原因；没有错误时为空。

时间统一以 UTC ISO 8601 写入，UI 转换为本地时间显示。历史创建总数统计所有成功登记的记录；当前有效数只统计最新状态为 `Valid` 且未删除的记录。

存储实现采用：

- `schemaVersion` 支持未来迁移；遇到高于当前版本的数据时只读打开。
- 单实例互斥量避免两个应用进程并发写入。
- 进程内异步写锁串行化保存。
- 同目录临时文件写入、刷新后原子替换正式文件，并保留最近一次有效备份。
- 解析或校验失败时保留损坏文件，尝试从备份恢复；恢复前保持只读并向用户说明。

## 5. 错误处理与可恢复性

- 校验错误直接显示在对应字段附近，包含可执行的修正建议。
- 创建、检查和删除操作显示明确进度并防止重复提交。
- 不支持的文件系统、同卷限制、网络路径限制、访问拒绝和路径占用分别显示具体原因。
- 状态检查失败不会删除历史记录，而是更新为 `Unknown` 并保留上一次成功信息。
- 数据目录不可写时应用进入只读记录模式；原生创建按钮禁用，防止出现无法登记的新链接。
- 任何删除保护验证失败都必须拒绝操作，不提供“强制递归删除”。

## 6. 测试策略

### 6.1 单元测试

- 路径规范化、大小写比较、根路径、UNC 和长路径处理。
- 四种类型的文件/目录、存在性、父目录、同卷及网络路径规则。
- 设备键散列、同设备改名和同名不同设备。
- 记录状态流转、历史与有效统计、设备/状态筛选和搜索。
- JSON 版本、原子保存、备份恢复、损坏文件和只读降级。
- ViewModel 的命令启用条件、验证消息、导航和删除确认。

### 6.2 Windows 集成测试

在测试临时目录中真实创建四种链接，并验证：

- 通过链接读取和修改内容时，源路径反映相同内容。
- 删除链接入口后源文件或源目录及其内容完整保留。
- 硬链接的文件标识一致，跨卷请求被拒绝。
- 符号链接和联接的重解析点类型及目标正确。
- 外部删除、外部替换和目标失效能得到正确状态，且冲突路径无法从应用删除。

依赖额外磁盘卷的测试在环境具备条件时运行，否则明确跳过；同卷核心测试不得跳过。

### 6.3 人工验收

- 每次启动出现 UAC，主界面正常加载。
- 文件/文件夹选择、直接输入和粘贴均可用。
- `B:\xxx2 → A:\xxx1` 创建后，A 保留且两个路径访问同一内容。
- 删除 B 后 A 及内容不受影响，记录转为已删除。
- 重启后记录、筛选和统计一致。
- 同一便携目录在两台 Windows 设备运行后，可切换查看各设备历史。
- 数据损坏、备份恢复和数据目录不可写均有明确且安全的表现。

## 7. 发布与开发前提

- 安装 .NET 10 SDK；当前开发机仅检测到 .NET 7 SDK，已有 .NET 10 Desktop Runtime 但不足以构建项目。
- 目标框架使用 `net10.0-windows`，发布 RID 为 `win-x64`。
- 发布采用 self-contained 单文件模式；调试符号与测试产物不进入便携发行目录。
- 应用程序、依赖和 `data` 目录放在同一发行根目录；升级程序时保留整个 `data` 目录。
- 首版只承诺 Windows 10/11 x64，本地卷主要按 NTFS 行为测试；其他文件系统以原生 API 实际返回能力为准并提供明确错误。

## 8. 完成标准

以下条件全部满足时，首版视为完成：

1. 四种链接均按 Windows 规则正确创建，并显示准确提示和限制。
2. 通过 B 访问 A 的内容，应用不复制、移动或重命名源。
3. 安全删除只移除链接入口，任何冲突或验证失败都不会误删普通路径。
4. 记录、统计、状态检查、历史保留和多设备切换在重启后保持一致。
5. 单元测试和必需的同卷 Windows 集成测试通过，人工验收项全部通过。
6. 自包含便携版可在未安装 .NET 运行时的受支持 Windows x64 设备启动。
