# 链接记录组织设计

## 意图与范围

为四种原生链接统一提供可选名称、单层分组及自动时间排序。创建页路径下增加选填记录信息；记录页支持编辑、分组筛选、字段搜索和折叠。原型批准后，用户取消手动排序，组内自动按创建时间排序。沿用深蓝 190.4 侧栏及固定尺寸浅色卡片。真实创建、检查、安全删除与只读降级保持现有边界。

## 元数据与身份

PersistedLinkRecord 保留位置构造器，增加 init 属性 CustomName、GroupId、SortOrder；名称仅用于记录，空白规范为 null，以 StringInfo 文本元素计数，最多 20，不静默截断、不套用文件名限制。LinkRecordMetadata 承载创建及重试时的名称和组。LinkRecordGroup 使用稳定 Guid、非空组名及非负顺序；组名去除首尾空白，按 Ordinal 判断重复。记录操作按 DeviceKey（Ordinal）与 Id 精确定位。

## 排序与查询

全局先按既有组 SortOrder，再按组内记录 CreatedUtc 倒序（最新创建在前）稳定排序；同一创建时间保留数据库原顺序，未分组永远置底。记录 SortOrder 元数据及底层移动能力保留兼容，界面无手动排序入口或调用。换组和解散组只变组织元数据，保留路径、创建时间与生命周期；显示统一遵循自动时间排序。过滤仅裁剪排序结果。搜索支持名称、源路径、链接路径和兼容原调用的综合路径搜索。设备、Deleted 语义与统计作用域保持原样。

## 持久化与兼容

LinkDatabase 保留位置构造器，增加默认空 Groups，当前 schema 为 2。读取 schema 1 后仅在内存升级、补空元数据和空组，保持记录顺序、身份、设备、时间、指纹与原生字段，读取不写盘；首次正常保存走既有原子安装与备份流程。schema 大于 2 继续只读。schema 2 验证组身份、重复组名、非负顺序、记录引用及名称；保留现有身份、生命周期验证。旧版读取 schema 2 时进入已有未来版本只读逻辑，防止覆盖新字段。

## 应用层与安全

LinkRecordOrganizationService 每次操作加载最新数据库，只通过 ILinkRecordStore 保存，不依赖原生链接服务。更新使用 with 保留所有非组织字段；取消和存储失败继续向调用者传播，只读由存储诊断及 SaveAsync 保护。创建和重试保留旧签名并提供带元数据的重载，原生创建前验证名称及组存在性，一次注册同时保存元数据。创建后登记失败结果保留元数据；原生提交后仍使用 CancellationToken.None，不重复创建链接。

## 方案选择

采用现有 JSON 数据库和小型组织服务，无第三方框架或通用仓储层。稳定 Guid 避免改组名影响引用；schema 2 优于无版本追加字段，因为旧应用会丢弃未知字段。一次注册优于创建后再补写名称，避免两次保存产生部分成功。暂不引入多级分组、标签及拖拽。F1 静态核查和双语用户文档归后续阶段。

## 可验收阶段

ORG-01：Domain、Application、JSON 存储及必要既有测试适配。ORG-02：WPF 创建、记录编辑、分组管理及组内自动时间排序。ORG-03：F1 静态诊断、双语文档与最终验收。每阶段独立验收后继续。

## WPF 接入

创建页在路径卡片后提供选填记录信息，文本元素计数和就地错误通过 RecordMetadataViewModel 绑定；忙碌或只读时冻结输入。名称和组选取的编辑不清除创建结果或 pending；登记重试始终传回 pending.Metadata 快照，创建结果中的同路径保护保留。

创建页将分组直接展示为可选列表，名称旁提供重命名和删除，另有新增按钮；“未分组”始终可选且不可重命名或删除。复用记录页的分组管理命令和确认对话框；删除后记录转入未分组，当前所选组被删除时回退为未分组，取消不保存。若分组被待重试登记引用，暂不允许删除该分组，以免失去待登记的原有分组；记录页管理窗口同样遵循此保护。

记录页保留原查询与删除用例，按组使用 Expander 展示，按 Guid 保存折叠和选择状态。默认名称搜索，字段可切换为源路径、链接路径或综合路径；清除筛选明确回到全部设备、全部分组、全部状态和空搜索。自动排序位于查询服务，界面不复制排序算法。页面进入时仍仅检查当前设备。

编辑和分组管理使用原生 WPF 对话框及文本绑定。组管理变更失败留在窗口提示；元数据保存失败在记录页明确提示。所有组织保存操作 finally 刷新共享存储状态。组合根共享组织服务和对话框服务，两个页面的 IsBusy 临时禁止跨页导航，避免异步保存期间切页发起另一次写入。
